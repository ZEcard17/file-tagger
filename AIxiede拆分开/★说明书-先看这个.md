## 一、我平时怎么启动？（最重要的一节）

**就一句话：双击这个文件就行。**

```
E:\桌面\MyPython\AIxiede.py
```

**怎么做**：
1. 打开 `E:\桌面\MyPython\` 这个文件夹
2. 找到 **`AIxiede.py`** 这个文件
3. **双击它**

**等 2～4 秒**，窗口就出来了。

**没有别的步骤** —— 不用装东西、不用敲命令、不用先打开别的软件。

> ★ 如果哪天双击**没反应**，看第七节「出问题怎么办」。

**可以放，会更方便。** 做法：

## 四、拆文件是干嘛的？有什么好处？

**以前**：3 万行代码全挤在一个文件里。
**改一个小地方，容易碰到别的地方** —— 这就是你遇到的「改着改着前面功能没了」。

**现在**：把 11 个「弹窗」搬到了隔壁的小文件里。

| 好处 | 说明 |
|---|---|
| **改一个弹窗，碰不到别的** | 比如改「挑标签」那个窗口，**绝对不会**影响到「扫进度」那个 |
| **主程序变清爽了** | 少了一万多行 |
| **万一拆坏了也不会打不开** | 每个零件都留了「保命代码」（见下） |

## 五、★★ 一个很重要的「保命机制」★★

**你可能会担心**：零件文件要是丢了、被删了，程序是不是就打不开了？

**不会。** 我给每个拆出去的地方都留了**一份保命代码**：

- **零件文件在** → 用零件文件（好维护）
- **零件文件不在** → **自动用主程序里那份保命代码**（程序照常开）

**你实际看到的**：程序窗口底部会多一行小字
`[提示] 拆出去的 XXX.py 没找到，已退回内置简易版`

**这就是保命机制在工作。程序一切正常，不用担心。**

## 七、出问题怎么办？

### 情况 1：双击没反应 / 窗口不出来

**先别慌。退回备份就行，一次就好。**

1. 打开 `E:\桌面\MyPython\` 文件夹
2. 找到名字最长的那个备份，比如：
   ```
   AIxiede.py.bak-拆13个成功-好用的-20261006-0146
   ```
3. **把这个备份复制一份**，改名成 `AIxiede.py`
4. 原来的 `AIxiede.py` **先改名**（比如加个「坏的」两字），别删

**就好。** 备份是「某个时间点好用的完整程序」，直接顶上来即可。

### 情况 2：程序能开，但某个功能不好使

1. 点右下角 **「🔔 问题」** 按钮 → 看里面写了什么
2. 菜单 **帮助 → 🩺 体检报告** → 把内容复制出来

**这两处会告诉你「哪儿出错了」，把内容发我就行。**

### 情况 3：界面有的地方显示不全

**正常画法出问题时，程序会自动用「保命画法」** ——
你会看到文件名照常列出来，顶上多一行红字提示。
**把提示内容发我。**

## 九、这次一共干了三件事（2026-10-05 晚 ~ 10-06 凌晨）

### 1️⃣ 修好了「拉动区域不记住比例」

**你原来遇到**：拉好了宽度，关了再开又乱了，有的太宽有的太窄。

**原因**：
- 程序开机时**抄到的是半成品宽度**（窗口还没摆稳），不是你自己拉的
- 而且「存」和「读」**接错线了** —— 存一个抽屉、读另一个抽屉

**现在**：只有你**亲手拉过**、或者**正常关程序**的时候才记比例。
**实测**：设 233/407/521 三个数字，关掉再开，**一个没变**。

### 2️⃣ 让程序「出错会说话」+ 加了「保命画法」

**你原来遇到**：界面显示不全、卡死，但不知道为什么。

**原因**：程序里有 **600 多处「出错了装没事」**，一声不吭。

**现在**：
- **菜单 帮助 → 🩺 体检报告**：列出了「哪儿在偷偷出错、出了几次」
- **后台线程崩了会被记下来**（卡死多半是它）
- **画不出来时有「保命画法」**：不会再是一片空白，至少看得见文件名
- 还修了一个真凶：**宽度量不到时它什么都不画** → 现在会照样画

### 3️⃣ 拆文件（拆了 11 个零件出去）

## 十、还想「上 Linux」的那件事

**现在还不能上 Linux。** 原因很简单：

程序里有**三四成是 Windows 专用的**：
- CloudDrive2 网盘挂载（`\\CloudDrive\X` 这种路径，Linux 上没有）
- pywin32（回收站、图标提取）
- `wmic` 查配置
- 各种 `E:\桌面\…` 这种写死的路径

**要上 Linux，得把这些一个一个换成 Linux 也能用的做法。**
这是一件**大工程**，得单独安排时间做，不能跟改 bug 一起做
（一起做会出问题分不清是谁的锅）。

**想推进的话，下一步该做的是**：把 Windows 专用的部分**标出来、隔离开**，
将来替换起来才方便。

## 十一、给「以后来帮忙的 AI」的一段话

如果你是 AI，接手这个项目，请先看这几条：

1. **主程序**：`E:\桌面\MyPython\AIxiede.py`（约 3 万行，单文件，中文注释）
2. **拆分结构**：`AIxiede拆分开\程序分块\` 里有 11 个零件。
   每个零件开头有 `_APP / _set_app / _grab / _fill / _link_siblings`，
   这是「不在开头 import 主程序、避免循环引用」的机制，**别删**。
3. **每个拆出去的地方，主程序里留了「转发 + 兜底」**
   （`try: from XXX import XXX … except: <原代码>`）—— **兜底别删**，
   它是「零件丢了程序也能开」的保险。
4. **`CategoryItem` / `CategorySidebar` 没拆成**，
   现在走兜底，功能正常。**再拆要特别小心行号边界**
   （上次就是这里算错，把两个类的代码搅在一起了）。
5. **改数据前先提醒用户备份**：
   `E:\简牍\.file_tagger.db`（约 400MB）和 `.file_tagger_settings.json`
6. **备份规矩**：改动前在 `MyPython\` 留
   `AIxiede.py.bak-<干了什么>-<年月日-时分>`，
   并把这次的改动写进文件开头的「更新记录」里。
7. **★ 铁律：绝不在 Tk 全局上动手脚**
   （不换 `tk.Tk.report_callback_exception`、不 patch `tk.Tk.xxx`）。
   2026-10-05 试过一次，**直接导致分栏条拖不动**。
8. **测试要用「假家目录 + 复制真数据库」**，
   绝不碰 `E:\简牍\` 里的真数据。
9. **不要 exec 主程序来测试** —— 它会自己跑 `mainloop`，
   把测试进程卡住。要用 `subprocess` 起独立进程。
