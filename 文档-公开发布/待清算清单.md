### 3. ✅ 已修（2026-10-07）「显示/隐藏顶部工具栏」第二次点跑到下面去了

- **现象**：用户「点了确实能隐藏，但再点显示在了下方，不再是顶部了」
- **真因（已确认，不是"推测"）**：恢复显示时写的是
  `self._top_bar.pack(fill="x")` —— **没给 `before=`**。
  **pack 不带 before 就是"排到最后面"**，于是两条工具栏被排到了
  `paned`（中间列表区）**下面**，看着就是"跑到下面去了"。
- **修法**：`pack(fill="x", before=self.paned)` +
  `pack(fill="x", before=self._top_bar2)`（顺序反了会上下颠倒，两条都要给）
- **实测**：隐藏前 `顶栏在第0位, 顶栏2在第1位, paned在第3位`；
  显示后 `顶栏→1, 顶栏2→2, paned→3`；**反复切 3 轮位置都对** ✔
- **★ 教训（通用）**：**`pack_forget()` 之后再 `pack()`，位置会丢** ——
  凡是"先藏起来、以后还要放回去"的控件，**放回去时必须给 `before=`/`after=`**。

### 4. ✅ 已修（2026-10-07）Ctrl+F 之后界面整体变淡

- **现象**：「用了以后界面变得很淡了」，近视看不清
- **真因（已确认）**：**不是 `focus_set()` 本身**，是它顺带触发的
  **"全选高亮"** —— Tk 的 Entry 拿到焦点、里面又有字时，会显示成**选中态**：
  浅色皮肤的 `select_bg = #cfe2ff`（浅蓝），**一满行浅蓝铺在搜索框里**，
  看着就是"界面变淡了"。
- **修法三件**：① 拿焦点后 `icursor(末尾)` + `selection_clear()` 去掉高亮；
  ② 再 `selection_clear()` 一次做双保险（不同 Tk 版本行为有差）；
  ③ 顺手把"正在搜什么"写进状态栏 —— 补上 #46 说的那种**反馈**
- **实测**：手动全选后 `selection_present = True`；
  走 `_focus_search_entry` 之后 `= False`；状态栏提示正常 ✔
- **★ 教训（通用）**：**"界面变淡/变色"这类问题，先怀疑"选中态 / 焦点态的颜色"**，
  别一上来就怪主题表 —— 主题表是对的，是**状态**触发的。

### 5. ✅ 已修（2026-10-08）资源管理器新建的空文件夹 → **无法右键**

- 现象：新建的空文件夹，打开后右键菜单不出来
- 要查：右键菜单是先选文件再弹的；**空文件夹**里 `rows` 为空时
  右键逻辑是否直接 return 了（应该有「空白处右键」这一路）
- ★ 这条要问清楚用户：是**在空文件夹的空白处右键**没反应，还是**选中那个文件夹本身**右键没反应？

**✅ 结案（2026-10-08）—— 清单里猜得对，就是"空白处直接 return"**

**两道门都关着**（所以空文件夹里右键**完全没反应**）：
```python
# FileList._on_right（第一道门）
idx = self._row_at_canvas(cx, cy)
if idx is None:
    return                 # ★ 没点到某一行 → 直接返回，菜单永远不出来

# FileTaggerApp.on_file_right_click（第二道门）
if not path:
    return                 # ★ 又是直接返回
```

**修法**：
- `FileList._on_right`：空白处**不再 return**，改调"空白处"回调
  （**不改变当前选中** —— 用户没点中文件，就别动他的选择）
- 主程序新增 `_popup_blank_menu()`：弹一个**"对整个目录"的菜单**
  （这是所有文件管理器的通用习惯，用户不用学）：
  - 📁 新建文件夹… / 📄 新建文本文件…
  - 🔄 刷新 / ⬜ 全选
  - 📂 在资源管理器里打开
  - 📋 粘贴到这儿（**剪贴板里没东西时自动变灰**）
- ★ **为什么不复用主菜单**：那个菜单全是"对选中文件做的事"
  （打标签/重命名/删除…），空白处没有选中文件 ——
  **摆一堆点不了的东西比不弹更糟**。

**实测**：
```
① 完全空的文件夹 → 8 项菜单 ✔
② 有文件的文件夹 → 空白处同样 8 项 ✔
③ 点中某一行     → 24 项「文件菜单」 ✔ 原来的没坏
新建文件夹 → 真的建出来了 ✔   新建文件 → 自动补 .txt ✔
同名重复   → 有提示、不覆盖 ✔  非法字符 → 自动替换成 _ ✔
取消（空） → 什么都不做 ✔
```

### 16. ✅ 已修（2026-10-08）文件列表的 **emoji 大小和字体大小不匹配**

- 用户：「文件列表的 emoji 大小和字体大小总是不太匹配」
- 根因：emoji 是**按像素画的图形**，字号变了它不会等比变
- 建议：emoji 尺寸**跟着 `UI_FONT_SIZE` 算**（比如 `UI_FONT_SIZE + 6`），
  而不是写死

**✅ 已修（2026-10-08）—— 建议的方向对，但基准要换成"字高"**

**实测证据**：
```
缩放 100% → 字高 25，最小档图标 22  → 差 −3
缩放 125% → 字高 30，最小档图标 22  → 差 −8   ★
缩放 150% → 字高 36，最小档图标 22  → 差 −14  ★
```
**修法**：`_ICON_STEPS = (1.0, 1.35, 1.95, 2.8, 4.2, 5.6)`，
  `图标像素 = round(字高 × 倍数)` —— **极小档 = 字高**（天生齐平）。
  ★ 为什么不用"`UI_FONT_SIZE + 6`"：真正决定"视觉齐不齐"的是
    **字高（linespace）**，同一个字号在不同 DPI/字体下字高不一样。

**实测（三档全齐）**：
```
100% → [25, 34, 49, 70, 105, 140]   最小档差 +0 ✔
125% → [30, 40, 58, 84, 126, 168]   最小档差 +0 ✔
150% → [36, 49, 70, 101, 151, 202]  最小档差 +0 ✔
换皮肤前后：最小档恒等于字高 ✔
```
**★ 附带**：加了 `refresh_icon_sizes()`，换缩放 / 换皮肤时各清一次缓存。

### O1. ✅ 已查清（2026-10-08）Alt+←/→ 的问题 —— 跟着 #6 一起修掉了

- 用户说「**Alt 加方向键切换上下文件预览正常**」
- 但 **Alt+←/→ 本来是主窗口的「后退 / 前进」快捷键**（`nav_back`/`nav_forward`）
- ★ 要查：是预览窗把这两个键吃了？还是主窗口的绑定被覆盖了？
- ★ 影响：用户可能已经发现「后退前进不好使了」但没意识到是冲突

**✅ 已查清 + 修掉（2026-10-08，跟 #6「预览窗提示没写 Alt」一起做的）**

**查清的事实**（比清单里猜的更准确）：
  · 「快速预览窗」**原来只绑了** `←` `→` `↑` `↓` 四个，
    **根本没绑 Alt+方向键**；
  · 用户按 **Alt+←/→ 之所以"也能换文件"**，是因为
    **主窗口**把这两个键当"后退/前进"用了
    → **目录切了 → 预览窗跟着换了内容**。
    **是"误打误撞"，不是预览窗抢了键。**
    ★ 所以"后退前进不好使"其实**没发生** —— 它是**正常**工作的，
      只是**副作用**恰好也把预览换了。

**修法**（在 #6 里一起做的）：
  1. **快速预览窗显式绑上 Alt+←/→/↑/↓**，并且**吃掉事件**（`"break"`）——
     预览窗开着时，Alt+方向键**只**换文件，**不再动主窗口目录**
  2. 提示文字写全

**实测**：
```
Alt+→ 第 1/2/3 次 → 文件 2/3/4 ✔
★ 而且主窗口目录**没变** ✔（这就证明事件被正确"吃掉"了，
   不再走"误打误撞"那条路）
Alt+← → 回上一个 ✔
```
