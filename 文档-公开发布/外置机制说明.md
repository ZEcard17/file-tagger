# 外置机制说明（零件 / 图标数据）

> **这份是写给"以后来改程序的人（或 AI）"的。**
> 2026-10-07 写。**改这个程序之前，先花两分钟看这份。**
>
> ★ 为什么要有这份：程序里现在有**两套"东西放在主程序外面"的机制**，
> 而且**规则不一样**（丢了以后，一个照常开、一个变 emoji）。
> 不知道这个区别，就很容易删错东西、或者白改。

---

## 一、现在有哪两套外置机制

| | **A. 拆出去的「零件」** | **B. 图标数据** |
|---|---|---|
| **放哪儿** | `AIxiede拆分开\程序分块\` | `图标资产\_icons_data.py` |
| **是什么** | 11 个对话框类（代码） | 17 个图标的 base64 数据 |
| **多大** | 11 个文件，合计约 **130 KB** | 1 个文件，约 **681 KB** |
| **丢了会怎样** | **程序照常开** | **程序照常开** |
| **具体表现** | 程序里那段 `except` 顶上，用**内置的简化版**；控制台打印一句「已退回内置简易版」 | 图标全部**变成 emoji**；打印一句「图标已退回 emoji 显示」 |
| **能删吗** | **能**（删了只是白拆，不影响程序） | **能**（删了图标变 emoji） |
| **主程序里还留着代码吗** | ★ **留着**（一份完整的兜底） | ✗ 不留（只有一句 `except`） |

**★ 一句话总结**：
> **两套外置，丢了都不会让程序打不开** —— 这是特意设计的。
> 但**主程序里为「零件」多留了一份代码**，所以那 11 个类**改的时候要改两处**。

---

## 二、★★ 最重要的一条：别删主程序里那 11 份「兜底」

**那 11 个零件，主程序里各留了一份完整代码**，长这样：

```python
try:
    from CategoryDialog import CategoryDialog, _set_app as _fk_CategoryDialog
    _fk_CategoryDialog(sys.modules[__name__])
except Exception:
    print("[提示] 拆出去的 CategoryDialog.py 没找到，已退回内置简易版")
    class CategoryDialog(tk.Toplevel):      # ← 这份就是"兜底"
        ...
```

**★ 为什么别删**：
- 删了之后，**零件文件夹一丢，程序就再也打不开**
- **实测验证过**（2026-10-07）：把 `SimpleInputDialog` 的兜底删掉，
  缺零件时直接抛 `SystemExit` —— **程序退出、窗口根本不出现**

**★ 那能省多少？**
- 删干净能省 **2,305 行 / 约 99 KB**，占主程序 **4.6%**
- **★ 不划算** —— 用一个"打不开"的风险换 4.6% 的体积，不值得

**★ 所以：改那 11 个类时，记住"改两处"**：
1. `AIxiede拆分开\程序分块\XXX.py`（正常走这份）
2. `AIxiede.py` 里那个 `except:` 下面的同名类（兜底那份）

**★ 忘了改第二处会怎样**：平时没事（走零件），
**但零件丢了以后，用户看到的是"老版本的界面"** —— 很难发现。

## 三、图标数据（B 套）—— 可以放心

**主程序里现在是这样的**：

```python
try:
    from _icons_data import ICON_PNG, ICON_TOTAL_BYTES
    _ICON_DATA_OK = True
except Exception:
    ICON_PNG = {}          # ← 保命：拿不到就退回 emoji
    _ICON_DATA_OK = False
```

**★ `图标资产\_icons_data.py` 丢了 = 图标变 emoji，程序照常开**（实测验证过）。

**★ 为什么当初要把它搬出去**：
它在主程序里占 **680 KB = 32%**（比 `FileTaggerApp` 主类还大近一倍），
是"程序臃肿"的**最大一块**。搬出去之后主程序
**2,152 KB → 1,474 KB（省 31.5%）**。

**★ 以后想"并回去"**（用户说过"图标资产以后再并回去"）：
把 `_icons_data.py` 里 `ICON_PNG[64]` 到 `ICON_TOTAL_BYTES` 那一段
**原样贴回主程序**（贴在 `from _icons_data import` 那个位置，替换掉那段 try），
再在主程序开头**删掉**加 `图标资产` 路径那几行。
**★ 并回去之后主程序会变回约 2,152 KB。**

## 四、这两个文件夹，能不能不跟程序放一起？

| 文件夹 | 不放一起会怎样 | 能单独挪走吗 |
|---|---|---|
| `AIxiede拆分开\` | 程序照常开，走内置兜底版 | 能，但白拆 |
| `图标资产\`（至少 `_icons_data.py`） | 程序照常开，图标变 emoji | **能，但图标会变 emoji** |

**★ 所以：程序**不会**因为少文件夹而打不开。**
（如果你哪天看到"双击没反应"，那**不是**这个原因，得去查别的。）

**★ 两个文件夹的位置都是用 `__file__` 推算的** ——
**整个 `MyPython` 文件夹搬到哪里都能用**，不用改代码。

## 六、★ 为什么 `FileTaggerApp` 不拆（有人问过）

**它 371 KB、8,204 行，是整个程序最大的块。但拆它没有意义：**

1. **它依赖 105 个"主程序里的名字"**（`DB_PATH`、`FONT`、`TagStore`、
   `PreviewPane`、`FileList`… 几乎全是核心）
2. **拆出去之后，那 105 个东西还是得在主程序里定义** ——
   `FileTaggerApp.py` 照样要 `import` 回来
3. **→ 总量一点没少，只是换了个地方**，还多了一层循环引用的风险

**★ 打个比方**：拆 `FileTaggerApp` = **把树干从树上拆下来** ——
剩下的枝叶还是得挂在它身上。

**★ 对比：什么样的能拆**（`CloudDriveApiClient` 只有 **7.6 KB**，
依赖**4 个常量** —— 这种拆起来才划算，但太小了，省不了多少）。

**→ 结论：主程序已经没有"独立的大块"可拆了。**
剩下的都是互相缠在一起的界面代码。**别为了"行数好看"去拆它。**

## 七、★ 改这个程序时，最容易踩的坑（跟外置有关的）

| 坑 | 后果 | 怎么办 |
|---|---|---|
| **改零件忘了改兜底** | 零件丢了以后用户看到老界面 | 改完**两处都改** |
| **搬代码段时漏掉紧挨着的前一行** | ★ 实测踩过：`ICON_PNG = {}` 那行在数据块**前面**，搬的时候漏了 → `NameError` → 被 `except` 吞掉 → **静默退回 emoji**（不报错，只是图标全没了） | 搬完**单独 import 一次新文件**核对 |
| 以为"图标能随便删" | 图标变 emoji | 删也行，但用户会看到 emoji |
| 以为"零件删了程序会挂" | —— | **不会**，有兜底 |

**★ 最后一条通用教训（很值钱）**：
> **兜底越完善，"静默失效"越隐蔽。**
> 因为 `except` 会把错误吞掉 —— **程序不崩、不报错，只是"功能好像没生效"**。
> ★ 所以：**改了外置的东西，一定要"单独喂真实数据跑一遍"**，
> 别只看"主程序语法通过"（那边有 `except` 兜着，什么都看不出来）。
